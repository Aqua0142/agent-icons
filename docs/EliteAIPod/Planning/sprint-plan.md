## Risks

- **[HIGH]** XSS vulnerability if server-side sanitization in T-003 is incomplete or if the frontend renders message content as raw HTML instead of text. High-priority security NFR.
  - _Mitigation:_ Enforce server-side HTML stripping in POST /messages (T-003). In the frontend timeline component (T-004), always set message content via textContent or equivalent safe API — never innerHTML. Include this as an explicit acceptance criterion at the human review gate.
- **[MEDIUM]** Race condition or duplicate submission if the Post button disable logic (T-005/T-006) is not correctly wired to the async request lifecycle, leading to multiple identical messages.
  - _Mitigation:_ Implement a single boolean 'isSubmitting' state flag that disables the button on request start and re-enables it on completion (success or error). Cover this with a manual test case at the review gate.
- **[MEDIUM]** Feed update after submission (T-006) relies on the API returning the full created message object from POST /messages (T-003). If the backend returns only a success status, the frontend cannot prepend the new message without a refetch.
  - _Mitigation:_ Explicitly specify in T-003 that the 201 response body must include the full message object (id, name, message, created_at). Verify this contract at the backend review gate before frontend integration.
- **[LOW]** No character limits defined for Name and Message fields (open question in PRD). Unbounded input could cause database truncation errors or UI layout issues.
  - _Mitigation:_ Apply reasonable defaults in the schema (T-001): name varchar(100), message text up to 2000 chars. Add client-side maxlength attributes in T-005. Flag the open question for the product owner to confirm limits.
- **[LOW]** Performance NFR requires message list to load within 3 seconds. For a demo-scale project this is low risk, but missing the created_at index could cause slow queries as data grows.
  - _Mitigation:_ Include the created_at DESC index in the T-001 schema migration. Verify query plan during backend review.
